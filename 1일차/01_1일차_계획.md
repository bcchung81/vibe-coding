## 1교시 · 원샷 환경설정 (09:30–10:30)

**목표**: 전원이 같은 도구 상태에서 출발한다. 설치 문제를 오전 안에 끝낸다.

| 시간 | 진행 |
|---|---|
| 09:30–09:40 | 오리엔테이션 — 이틀의 흐름 · **교육용 API 키 배포** · 키 보안 수칙(공유 금지, 화면 공유·캡처 주의, 교육 종료 시 자동 무효) |
| 09:40–10:20 | 실습 — `00_환경설정.md` Part A의 "교육 당일" 단계 → Part B 원샷 실행 |
| 10:20–10:30 | `환경점검결과.md` 확인 · 미완료자 명단 작성 → 조교가 2교시 실습 중 개별 처리 |

**수강생이 하는 일**
1. 키 저장 → `claude` 실행 → `@00_환경설정.md 파일의 Part B를 처음부터 순서대로 진행해줘`
2. 에이전트가 안내하면 GitHub · Vercel · Supabase 로그인 (`! 명령` 입력)
3. 재시작 후 `/mcp` 로 sequential-thinking · kordoc 연결 확인, `/impeccable` 확인

**강사 포인트**
- 이 시간 자체가 첫 교재다. **"한 파일의 지시문으로 에이전트가 내 PC를 설정했다"** 는 경험이 2교시 하네스 이야기의 도입이 된다.
- 에이전트가 사람에게 넘긴 일(로그인·권한·비밀번호)을 짚어 준다 — "에이전트가 할 일과 사람이 할 일의 경계".

**자주 막히는 곳 → 조교 대응**

| 증상 | 대응 |
|---|---|
| 설치 직후 `command not found` | 재시작 (`/exit` → 새 터미널 → `claude --continue`) |
| 재시작 후 키를 다시 묻는다 | Windows `setx` 누락 / macOS `~/.zshrc` 누락 |
| `winget` 없음 | Microsoft Store "앱 설치 관리자" 업데이트 |
| 사내 인증서 오류 | 인터넷망 PC인지 확인. 안 되면 강사 예비 노트북 |
| Windows MCP `✗ Failed` | `claude mcp get kordoc` 로 `cmd /c` 가 `C:/` 로 바뀌었는지 확인 |

**강사 준비물**: 개인별 키 봉투 30개(`edu-01`~`edu-30`) · 예비 노트북 2대 · Console 사용량 화면(강사 PC)

## 2교시 · 하네스 구조 해부 (10:40–12:00)

**목표**: 방금 설치된 것들이 각각 무슨 역할인지 설명할 수 있다. 잘 만든 하네스 2개를 뜯어 보고 직접 써 본다.

### 강의 (30분) — 구성요소 지도

| 구성요소 | 어디에 | 언제 읽히나 | 한 줄 정의 |
|---|---|---|---|
| CLAUDE.md | `~/.claude/` (전역) · 프로젝트 폴더 | 세션 시작마다 | 에이전트에게 주는 상시 지침 |
| settings.json | `~/.claude/` · `.claude/` | 항상 | 권한 · 모델 · 환경변수 · 훅 |
| 권한 모드 | 실행 옵션 · 설정 | 도구 실행마다 | 무엇을 묻고 무엇을 바로 할지 |
| 스킬 | `skills/` | 필요할 때만 | 반복 업무 절차를 파일로 |
| 커맨드 | `commands/` | `/이름` 입력 시 | 자주 쓰는 지시의 단축키 |
| 훅 | settings.json `hooks` | 정해진 순간마다 (예: 파일 저장 후) | 에이전트가 잊어도 반드시 도는 검사 |
| 플러그인 | 마켓플레이스 | 설치 후 | 스킬·커맨드·훅·MCP를 묶은 배포 단위 |
| MCP | `claude mcp add` | 도구 호출 시 | 외부 프로그램에 연결하는 표준 규격 (2일차 본격) |

**실례로 보여 줄 것** (강사 화면)

1. **CLAUDE.md 행동지침** — 운영 중인 기관 서비스 3곳의 CLAUDE.md에 같은 행동지침이 들어 있다.
   - 코딩 전에 생각하기 · 단순함 먼저 · 외과적으로 고치기
   - 메시지: "프로젝트가 달라도 에이전트의 나쁜 습관은 같다."
2. **claudian** — CLAUDE.md 한 장이 일반 챗봇을 '규율 있는 위키 관리자'로 바꾼다.
   - 3레이어: 원본(raw) / 위키 / 스키마(CLAUDE.md)
   - 사람 승인 없이 스키마를 고치지 않는다는 규칙
3. **report-harness** — 2일차 예고.
   - 초안을 저장하면 린트 훅이 자동으로 돈다.
   - 같은 지적이 2번 나오면 규칙(R001~)으로 승격된다 — "쓸수록 좋아지는 하네스".
4. **권한 모드** — claudian 배포판은 기본값을 '전권 위임'에서 '편집만 허용'으로 낮췄다. 비전문가에게 전권 위임은 위험하기 때문이다.

### 실습 (40분) — claudian으로 개인 위키 시작

1. claudian 배포판을 내려받아 실습 폴더 옆에 풉니다 (강사가 ZIP 제공).
2. 그 폴더에서 `claude` 실행.
3. `/ingest 샘플.hwpx` → kordoc MCP가 호출되어 한글문서 본문·표가 마크다운으로 풀린다.
   - 내장 이미지 추출은 OS마다 쓰는 도구가 다르다 (pyhwp · PyMuPDF · macOS 전용 `sips` 등). 수강생 PC에서는 건너뛰어도 되고, 이미지 처리는 강사 화면으로 보여 준다.
4. 생성된 위키 페이지(`concepts/`·`entities/`)와 `wiki/log.md` 를 확인한다. Obsidian이 있으면 그래프 화면으로 본다.
5. `/query 샘플 문서의 핵심 수치 3개` → 위키에서 답하는지, 출처 경로가 붙는지 확인한다.

**확인 질문**: "방금 kordoc을 부른 건 누구의 판단이었나? CLAUDE.md의 어떤 문장 때문인가?"

### 정리 (10분)

- 내 업무폴더를 하나 만들고 `/init` → 생성된 CLAUDE.md에 행동지침 3줄을 붙인다.
- 이 폴더가 3·4교시 미니앱의 작업폴더가 된다.

**강사 준비물**: claudian 배포판 ZIP(공개 저장소 `bcchung81/claudian` 기준 — 배포판 위치 확정 필요) · 표 위주 샘플 hwpx 1종 + 그림 포함 hwpx 1종(강사 시연용) · 운영 서비스 CLAUDE.md 발췌(민감정보 제거판)

## 3교시 · 미니앱 기획 (13:00–14:30)

**목표**: 만들기 전에 "무엇을 · 어떤 순서로 · 무엇이 되면 끝인지"를 문서로 고정한다.

| 시간 | 진행 |
|---|---|
| 13:00–13:20 | 강의 — 바이브코딩 작업 순서 |
| 13:20–14:20 | 실습 — 주제 선택 → PRD → 계획 → 검증 기준 |
| 14:20–14:30 | 짝 리뷰 |

### 강의 (20분)

- **작업 순서**: 요구사항 → PRD → 구현 계획(plan mode) → **검증 기준 먼저** → 단계별 구현
- **검증 기준을 먼저 쓰는 이유**: 에이전트는 "됐다"고 말하는 데 능하다. 무엇을 보면 됐다고 할지를 사람이 먼저 정해야 한다.
- **운영 사례**
  - 성과돋보기: 계획 문서 2층(로드맵 · 실행 플랜), 태스크마다 "실패 테스트 → 구현 → 통과"
  - 경영평가 Sherpa: CLAUDE.md에 "어기면 깨지는 것"만 모아 둔다

### 미니앱 주제 (택 1)

| 구분 | 기본안 — 공공데이터 조회 도구 | 심화안 — 규정 Q&A 챗봇 |
|---|---|---|
| 하는 일 | 공공데이터포털 API로 조회하고 표·지도·차트로 보여 줌 | 규정 문서 몇 개를 넣고 질문하면 근거와 함께 답함 |
| 외부 호출 | 공공데이터포털 (무료 키) | Claude API (교육용 키) |
| 축소판 원본 | 운영 중인 상황판 서비스 | 운영 중인 이음5G 챗봇 · 규정·법령 어드바이저 |
| 2일차 기준과 연결 | 키 서버 전용 · 키 한도 · 오류 숨김 | 레이트리밋 · 토큰 예산 · 인용 검증 |

공통 기술: Next.js(App Router). **외부 API는 반드시 서버 쪽 라우트에서 부른다** — 2일차 기준 ①의 복선.

### 실습 (60분)

1. 에이전트에게 인터뷰를 시킨다.
   ```
   내가 만들 앱에 대해 질문을 5개 이하로 하나씩 물어보고, 답을 모아 PRD.md를 써줘
   ```
2. plan mode(Shift+Tab)로 전환 → `PRD.md를 읽고 5단계 이하 구현 계획을 PLAN.md로 써줘. 단계마다 '완료 기준'을 넣어줘`
3. 완료 기준이 **눈으로 확인 가능한 문장** 인지 고친다.
   - 나쁜 예: "API 연동 완료"
   - 좋은 예: "`/api/search?q=서울` 이 JSON 10건을 돌려준다"

### 짝 리뷰 (10분)

옆 사람의 PRD에서 두 가지를 묻는다.
1. 외부 API 키는 어디에 두나?
2. 실패하면 화면에 무엇이 뜨나?

답을 못 하면 PRD에 추가한다.

**강사 준비물**: 공공데이터 API 1~2종 지정(사전과제로 활용신청) · 승인 지연자용 샘플 응답 JSON · 심화안용 규정 샘플 문서 3건

## 4교시 · 미니앱 구현 (14:40–16:40)

**목표**: PLAN.md의 단계를 하나씩 끝내며 로컬에서 도는 앱과 GitHub 저장소를 만든다.

| 시간 | 진행 |
|---|---|
| 14:40–14:50 | 시연 — 강사가 1단계를 구현 → 실행 → 커밋까지 한 바퀴 |
| 14:50–15:30 | 실습 ① — 프로젝트 생성 · 서버 라우트에서 외부 API 호출 |
| 15:30–15:40 | 미니 강의 — 막혔을 때 디버깅 루프 |
| 15:40–16:30 | 실습 ② — 화면 · 다듬기 · 커밋 · GitHub push |
| 16:30–16:40 | 도전 과제 안내 · 정리 |

### 실습 흐름

1. `PLAN.md 1단계를 구현해줘. 끝나면 완료 기준대로 직접 확인하고 결과를 보여줘`
2. 단계마다 `npm run dev` 로 브라우저에서 확인 → 확인되면 커밋 (`이 단계 커밋해줘`).
3. 공공데이터 키는 `.env.local` 에 넣는다. **에이전트에게 키 값을 말하지 않는다** — 파일에 직접 붙여 넣는다.
4. 화면이 돌면 `/impeccable polish` 로 디자인을 다듬는다 (1교시에 설치한 플러그인).
5. `GitHub에 비공개 저장소를 만들고 올려줘` → `gh repo create` 로 push.

### 미니 강의 (10분) — 막혔을 때

- 오류 원문을 그대로 붙여 넣는다. 요약하지 않는다.
- "원인 가설 3개와 확인 방법부터 말해줘" — 고치기 전에 진단부터 시킨다.
- 한 번에 하나만 고친다. 두 번 실패하면 접근을 바꾸라고 지시한다.
- 대화가 길어져 헤매면 `/clear` 후 PLAN.md부터 다시 읽힌다 — **맥락은 대화가 아니라 파일에 둔다.**

### 도전 과제 (끝난 사람)

- Supabase 프로젝트를 만들어 조회 기록을 저장한다 (`supabase` CLI · 연결 문자열은 `.env.local`).
- 2일차 기준 ⑥(운영 데이터 보호)의 실습 재료가 된다.

**완료 기준**: 로컬에서 앱이 돌고, GitHub에 커밋 3개 이상이 올라가 있다.
