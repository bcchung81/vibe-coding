| 14:00–14:15 | 에이전트가 Part B로 점검 · 로그인 → `환경점검결과.md`. 못 끝낸 사람은 2교시 중 조교가 이어서 처리 |

**수강생이 하는 일** — 근거: `교육생_배포/2_1일차_당일/00_환경설정.md`
1. 강사가 준 파일 3개(`setup.ps1` · `00_환경설정.md` · `AGENTS.global.md`)를 `C:\workspace` 에 저장한다.
2. **일반 PowerShell 창**(관리자 아님)에서 실행한다.
   ```powershell
   cd C:\workspace
   powershell -ExecutionPolicy Bypass -File .\setup.ps1
   ```
   - `LAW_OC` 를 물으면 1일차만 참여자는 Enter로 넘어간다 (2일차 작은 업무 · 보고서용).
3. 창을 모두 닫고 새 창에서 내 에이전트를 실행한 뒤 입력한다.
   ```
   00_환경설정.md 파일을 읽고 Part B를 순서대로 진행해줘
   ```
4. 에이전트가 안내하는 브라우저 로그인을 직접 처리한다. 오늘은 GitHub · **Vercel(4교시 배포)** 이 꼭 필요하고, Supabase는 건너뛰어도 된다.

**강사 포인트**

- 에이전트가 사람에게 넘긴 일(로그인 · 관리자 확인 · 인증값 입력)을 짚는다 — **에이전트가 할 일과 사람이 할 일의 경계**.

**자주 막히는 곳 → 조교 대응** (전체 목록은 `00_환경설정.md` 부록)

| 증상 | 대응 |
|---|---|
| "디지털 서명되지 않았습니다" | `Unblock-File .\setup.ps1` 후 다시. "그룹 정책" 메시지면 전산부서 |
| `Continue anyway? (y/N)` | 관리자 창에서 실행한 것. Enter로 멈추고 일반 창에서 다시 |
| 설치했는데 `명령을 찾을 수 없습니다` | 창을 모두 닫고 새 창 → 안 되면 `setup.ps1` 다시 실행(PATH 보정) |
| 에이전트가 API 키로 로그인됨 | 별도 창에서 로그아웃 → **구독 계정** 으로 다시 로그인 |

**강사 준비물**: 파일 3개 배포 수단 · 예비 노트북 · `환경점검결과.md` 수합 방법

**주제 카드에 공통으로 넣을 것** (3 · 4교시에 쓴다)
- **Decoding 키** 를 `.env.local` · Vercel 환경변수에 넣는다. Encoding 키는 이중 인코딩되어 `SERVICE_KEY_IS_NOT_REGISTERED_ERROR` 가 난다.
- 파라미터 이름이 API마다 다르다.
  - 키 이름: `serviceKey`(1·3·4·7·8·9·10), `ServiceKey`(2·5·6)
  - JSON 응답 지정: `_type=json`(1·7·8), `dataType=JSON`(2), `returnType=json`(3·10), `type=json`(4·5)
- Vercel 배포는 `vercel.json` 에 `{"regions":["icn1"]}` 를 넣는다.
  - 기본 리전(미국)에서 `apis.data.go.kr` 연결이 시간 초과된 사례가 있다(비공식 측정).
  - Hobby 플랜도 단일 리전 지정이 된다(문서 기준, 리허설에서 확인).
- 자동승인이어도 키 반영에 1~2시간 걸릴 수 있다.
  - 사전과제 마감은 교육 2~3일 전으로 잡는다.
  - 테스트 URL의 `resultCode 00` 화면 캡처를 제출받는다.
- 키는 수강생 본인 것을 쓴다. 일일 한도가 1인 기준이라 강사 키를 함께 쓰지 않는다.

## 3교시 · 웹앱 만들기 — 예시 데이터 → 실제 API → 디자인 (15:15–16:25)

**목표**: 스냅샷 데이터로 화면을 먼저 돌리고, 같은 서버 라우트를 실제 공공데이터 API로 바꾼다. 키는 서버에만 둔다. (과정 목표 2)

| 시간 | 진행 |
|---|---|
| 15:15–15:45 | 스냅샷 데이터로 화면 만들기 → 기능 붙이기 |
| 15:45–15:50 | 강의 — 키는 어디에 두나 |
| 15:50–16:10 | 실습 — 스냅샷 → 실제 호출 |
| 16:10–16:25 | impeccable로 디자인 다듬기 · 완료 기준대로 점검 |

### 화면 만들기 (30분)

1. 한 단계씩: `/vibe-step` 을 단계마다 부른다 — 그 단계만 구현하고 완료 기준대로 확인한다. 단계마다 `npm.cmd run dev` 화면을 브라우저로 본다.
2. 30분이 되면 화면 단계가 덜 끝났어도 API 단계로 넘어간다. 남은 화면 단계는 디자인 시간에 마저 한다.

### 강의 (5분) — 키는 어디에 두나

- **키는 서버에만**: `.env.local` → 서버 라우트(`/api/...`)에서만 읽는다. 키 이름에 `NEXT_PUBLIC_` 을 붙이면 브라우저로 새어 나간다.
- **에이전트에게 키 값을 말하지 않는다**: 파일에 사람이 직접 붙여 넣는다. 대화 기록에 남지 않게 한다.
- **Decoding 키** 를 쓴다. Encoding 키는 이중 인코딩되어 `SERVICE_KEY_IS_NOT_REGISTERED_ERROR` 가 난다.
- **실패해도 화면은 돈다**: 호출이 실패하면 스냅샷을 대신 보여 주고 "예시 데이터" 표시를 붙인다.

### 실습 (20분) — 스냅샷 → 실제 호출

1. 공공데이터포털 마이페이지에서 **Decoding 키** 를 복사해 `.env.local` 에 직접 넣는다 (`시작하기.md` 3번).
   ```
   DATA_GO_KR_KEY=붙여넣기
   ```
2. `/vibe-step` — `PLAN.md` 의 실제 API 단계를 한다. 시작 폴더 밖이면 이렇게 시킨다.
   ```
   서버 라우트가 snapshot.json 대신 공공데이터 API를 부르게 바꿔줘. 키는 process.env.DATA_GO_KR_KEY에서 읽고, 파라미터는 주제 카드의 표를 따라. 호출이 실패하면 스냅샷을 대신 보여 주고 화면에 '예시 데이터'라고 표시해줘
   ```
3. `npm.cmd run dev` 로 실제 데이터가 뜨는지, 키를 지우면 "예시 데이터"로 도는지 확인 → 커밋.

**자주 막히는 곳 → 조교 대응**

| 증상 | 원인 | 대응 |
|---|---|---|
| `SERVICE_KEY_IS_NOT_REGISTERED_ERROR` | Encoding 키를 넣었거나 키 반영 전 | Decoding 키로 바꾼다. 그래도 나면 브라우저 주소창에서 테스트 URL로 키만 따로 확인 |
| JSON 대신 XML이 온다 | JSON 지정 파라미터 이름이 틀림 | 주제 카드의 파라미터 표(`_type` · `dataType` · `returnType` · `type`) |
| `LIMITED_NUMBER_OF_SERVICE_REQUESTS_EXCEEDS_ERROR` | 일일 한도 초과 (에어코리아 500회) | 라우트에 캐시를 두고, 오늘은 스냅샷으로 진행 |
| 키가 아직 승인 안 됨 | 사전과제 미완료 | 스냅샷 그대로 진행 — 화면과 배포는 같다 |

### 디자인 다듬기 (15분)

- 화면이 돌면 `impeccable 스킬로 이 화면을 다듬어줘` (1교시에 설치한 스킬).
- 끝나면 `PLAN.md` 의 완료 기준을 하나씩 브라우저로 확인한다.

### 막혔을 때 (실습 중 3분 안내)

- 오류 원문을 그대로 붙여 넣는다. 요약하지 않는다.
- "원인 가설 3개와 확인 방법부터 말해줘" — 고치기 전에 진단부터 시킨다.
- 한 번에 하나만 고친다. 두 번 실패하면 접근을 바꾸라고 지시한다.
- 대화가 길어져 헤매면 새 세션에서 `PLAN.md` 부터 다시 읽힌다 — **맥락은 대화가 아니라 파일에 둔다.**
- 시작 폴더의 `/vibe-fix` 가 이 순서를 그대로 시킨다 (오류 원문 → 가설 3개 → 하나씩).
- 이 원칙을 스킬로 만든 예: superpowers 플러그인의 systematic-debugging(강사 화면으로 소개만)
