### 주제 후보 — 기관(KCA) 업무 데이터

강사가 이 중에서 골라 확정한다(☐ → ✅). 확정한 주제의 API만 사전과제로 활용신청을 안내한다.

- 2026-11-07 공공데이터포털 명세로 **2 · 3 · 6을 골라 주제 카드 01 · 02 · 03으로 만들었다**. 같은 날 강사 계정으로 셋 다 활용신청(모두 자동승인)하고 강사 키로 바로 불러 예시 데이터를 받았다(`npm run snapshots` → 시작 폴더 `data\01~03.json`).
- 파일데이터 3개 모두 포털 자동변환 API가 있다. 검색 변수 없이 `page` · `perPage` 만 있어 전부 받은 뒤 화면에서 거른다.
- 자격증 진위여부 API는 개인 자격번호를 넣어야 해서 뺐다.
- 뺀 이유: 1은 API 유형이 LINK(기관 사이트 키) · 4는 필수 변수에 넣을 값 목록이 없음 · 5는 65만 행인데 검색 변수가 없어 실제 API 단계가 의미 없음.

**주제 카드에 공통으로 넣을 것** (3 · 4교시에 쓴다)
- **Decoding 키** 를 `.env.local` · Vercel 환경변수에 넣는다. Encoding 키는 이중 인코딩되어 `SERVICE_KEY_IS_NOT_REGISTERED_ERROR` 가 난다.
- 키 이름(`serviceKey` · `ServiceKey`)과 JSON 지정 변수 이름이 API마다 다르다 — 카드에 표로 못 박는다.
- Vercel 배포는 `vercel.json` 에 `{"regions":["icn1"]}`. 기본 리전(미국)에서 `apis.data.go.kr` 연결이 시간 초과된 사례가 있다(비공식 측정).
- 자동승인이어도 키 반영에 1~2시간 걸릴 수 있다. 사전과제 마감은 교육 2~3일 전, 테스트 URL의 `resultCode 00` 화면 캡처를 받는다.
- 키는 수강생 본인 것을 쓴다. 일일 한도가 1인 기준이라 강사 키를 함께 쓰지 않는다.

### 화면 만들기 (25분)

1. 별도 PowerShell 창에서 `npm.cmd run dev` 를 켜 둔다.
2. `vibe-develop 스킬로 다음 단계 해줘` — 그 단계만 구현하고, 에이전트가 ego-browser로 `localhost:3000` 을 열어 완료 기준대로 눌러 본 뒤 통과 표로 보고한다.
3. 사람도 브라우저를 새로고침해 한 번 본다. ego-browser가 안 되는 PC는 에이전트가 볼 것을 알려 주고 사람이 판정한다.
4. 15:45가 되면 화면 단계가 남아도 API 단계로 넘어간다. 남은 화면은 디자인 시간에.

### 키 넣기 → 실제 API (25분)

1. 공공데이터포털 마이페이지에서 **Decoding 키** 를 복사해 `.env.local` 에 직접 넣는다(별도 창 · 메모장).
   ```
   DATA_GO_KR_KEY=붙여넣기
   ```
2. `vibe-develop 스킬로 다음 단계 해줘` — `PLAN.md` 의 실제 API 단계. 호출이 실패하면 예시 데이터를 보여 주고 "예시 데이터"라고 표시한다.
3. 실제 데이터가 뜨는지, 키를 지우면 "예시 데이터"로 도는지 확인 → 커밋.

| 증상 | 원인 | 대응 |
|---|---|---|
| `SERVICE_KEY_IS_NOT_REGISTERED_ERROR` | Encoding 키 · 키 반영 전 | Decoding 키로 바꾼다. 그래도 나면 테스트 URL로 키만 따로 확인 |
| JSON 대신 XML이 온다 | JSON 지정 변수 이름이 틀림 · XML만 주는 API | 주제 카드의 변수 표. XML이면 통로에서 JSON으로 바꾼다 |
| `LIMITED_NUMBER_OF_SERVICE_REQUESTS_EXCEEDS_ERROR` | 일일 한도 초과 | 통로에 캐시를 두고 오늘은 예시 데이터로 |
| 키가 아직 승인 안 됨 | 사전과제 미완료 | 예시 데이터 그대로 진행 — 화면과 배포는 같다 |

### 디자인 다듬기 (15분)

- `vibe-design 스킬로 화면 다듬어줘` — impeccable 스킬로 다듬고 완료 기준을 다시 본다.
- 마지막에 `vibe-develop 스킬로 PLAN.md 완료 기준을 ego-browser로 전부 점검해줘`.

### 막혔을 때 (실습 중 3분 안내)

- 오류 원문을 그대로 붙여 넣는다: `vibe-develop 스킬로 이 오류 고쳐줘` 다음 줄에 원문.
- 고치기 전에 진단부터 — 원인 가설 3개와 확인 방법. 한 번에 하나만 고친다. 두 번 실패하면 접근을 바꾼다.
- 대화가 길어져 헤매면 새 세션에서 `PLAN.md` 부터 다시 읽힌다 — **맥락은 대화가 아니라 파일에 둔다.**

### 강의 (5분) — 구조도 ④ 배포 구조

| 단계 | 그림에서 강조 | 말할 것 |
|---|---|---|
| 1 | 점검 3가지 | 공개하기 전에 내 PC에서 |
| 2 | 내 PC → Vercel CLI → Vercel(icn1) | 에이전트가 배포한다. 서울 리전 |
| 3 | 환경변수 | 키 값은 사람이 별도 창에서 넣는다 |
| 4 | 공개 주소 → ego-browser 점검 | 잘못된 입력에 오류 원문이 안 보이나, 휴대폰 너비에서 깨지지 않나 |

### 배포 전 점검 3가지

| # | 점검 | 확인 방법 |
|---|---|---|
| 1 | 키가 git에 올라가지 않았다 | `.env.local` 이 `.gitignore` 에 있고 `git status` 에 보이지 않는다 |
| 2 | 키 없이도 빌드된다 | `npm.cmd run build` 통과 |
| 3 | 오류 원문이 화면에 안 보인다 | 잘못된 입력에 일반 문구만. 원문은 서버 로그에만 |

### 실습 (15분)

1. `vibe-develop 스킬로 배포 전 점검해줘` → 통과하면: `이 폴더를 Vercel 프로덕션으로 배포해줘. 환경변수는 내가 직접 넣을 테니 넣을 이름만 알려줘`
2. 환경변수 값은 **별도 PowerShell 창** 에서 직접: `vercel.cmd env add DATA_GO_KR_KEY production`. 키가 없는 사람은 건너뛴다 — 예시 데이터로 뜬다.
3. 다시 배포한 뒤: `ego-browser 스킬로 배포 주소를 열어 잘못된 입력을 넣어 보고, 휴대폰 너비로 줄여서 캡처해줘`.
   - 공유는 프로젝트 기본 주소(`프로젝트이름.vercel.app`)로 한다. 배포마다 생기는 긴 주소는 로그인 보호 때문에 남에게 안 열릴 수 있다.

### 서로 열어 보기 · 마무리 (10분)

1. 내 기본 주소(`프로젝트이름.vercel.app`)를 옆 사람에게 보여 주고, 서로 휴대폰으로 열어 본다.
2. 강사가 2~3명을 골라 강사 화면으로 소개한다.
3. 만든 것은 내 계정과 PC에 남는다 — `C:\workspace\vibe` · Vercel 주소(공개 상태). 내리려면 Vercel 대시보드에서 프로젝트를 삭제한다. GitHub 비공개 저장소에 올리기는 선택이다.
4. **1일차만 참여자**: 수료 · 설문. 공용 PC면 `codex logout`. **이틀 참여자**: 내일 1교시 조사를 마치고 남는 시간에 주제 카드 "향후 고도화" 하나를 해 본다.

**강사 준비물**: 소개할 수강생 주소를 강사 PC에서 여는 방법(주소를 불러 받아 입력)
