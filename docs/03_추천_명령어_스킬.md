# 추천 명령어 · 스킬 — 기본 제공이 아닌 것

> 강사 PC(macOS)에 설치된 커스텀 명령 · 스킬 · 플러그인 가운데 교육에 쓸 것을 골랐다. 2026-10-21 확인.
> 수강생 PC 설치는 모두 `setup.ps1` 이 한다. 교육 중에는 새로 설치하지 않는다.

**고르는 기준**
1. 세 에이전트(Codex · Claude Code · Antigravity)에서 같이 돈다.
2. 본인 구독 1개로 된다. 다른 에이전트 구독이나 유료 API 키가 필요 없다.
3. Windows · PowerShell에서 돈다.
4. 구독 사용량 부담이 작다. 하위 에이전트를 여럿 돌리거나 high effort를 쓰지 않는다.
5. 비개발자가 결과를 보고 판단할 수 있다.

## 커스텀 명령은 파일 하나다 (1일차 2교시 · 2일차 2 · 4교시)

자주 쓰는 지시를 매번 치는 대신 파일로 둔다. `/think` 는 15줄짜리 지시문 한 장이다.

| 에이전트 | 만드는 곳 | 부르는 법 |
|---|---|---|
| Claude Code | 명령 `~\.claude\commands\이름.md` 또는 스킬 `~\.claude\skills\이름\SKILL.md` | `/이름 내용` |
| Codex | 스킬 `~\.agents\skills\이름\SKILL.md` | `/skills` 에서 확인하고 이름을 불러 시킨다 |
| Antigravity | 스킬 `~\.gemini\config\skills\이름\SKILL.md` · 워크플로(Customizations → Workflows) | 스킬은 이름을 불러 시키고, 워크플로는 `/이름` |

- 세 에이전트에 같은 명령을 주려면 **스킬** 로 만든다. `setup.ps1` 이 `think` 를 이렇게 설치한다.
- Antigravity 워크플로 위치와 `/이름` 호출은 Windows 리허설에서 확인한다.
- 2일차 4교시에 수강생이 이 표의 스킬 폴더에 **내 명령을 직접 만든다** (`02_2일차_계획.md`).

## A-2. 시작 폴더 명령 — `vibe.zip` 에 들어 있다 (설치 없음)

1일차 2교시에 `C:\workspace\vibe` 로 푸는 시작 폴더(원본 `docs/교육생_배포/vibe/`)의 프로젝트 명령. 교안의 프롬프트를 명령으로 묶었다. `.agents\skills`(Codex · Antigravity)와 `.claude\skills`(Claude Code)에 같은 내용으로 있고, "vibe 명령을 전역에도 설치해줘" 하면 에이전트가 전역 스킬 폴더로 복사한다.

| 이름 | 하는 일 | 쓰는 교시 |
|---|---|---|
| vibe-prd | 주제 카드를 읽고 질문 5개 이하로 인터뷰 → `PRD.md` | 1일차 2교시 |
| vibe-plan | `PLAN.md` — 화면 4단계 이하, 단계마다 완료 기준 + 실제 API 단계 | 1일차 2교시 |
| vibe-step | 안 끝난 첫 단계 하나만 구현하고 완료 기준대로 확인 | 1일차 3교시 (이틀 참여자는 2일차 1교시 고도화에도) |
| vibe-fix | 오류 원문 → 원인 가설 3개 · 확인 방법 → 하나씩 고치기 | 막혔을 때 |
| vibe-check | 배포 전 점검 3가지(키가 git에 없나 · 키 없이 빌드되나 · 오류 원문이 안 보이나) | 1일차 4교시 |

- 이름에 `vibe-` 를 붙인 이유: Codex 기본 스킬 `plan` 등과 겹치지 않게 하고, `/vibe` 만 쳐도 다섯 개가 함께 뜨게 했다.

## B. 강사 시연 — 수강생 PC에는 설치하지 않는다

| 이름 | 하는 일 | 보여 줄 때 · 메시지 | 실습에서 뺀 이유 |
|---|---|---|---|
| `/scout-tdd` | 만들기 전에 GitHub · 패키지 저장소에서 이미 있는 것을 찾는다. 별 수 · 최근 커밋 · 라이선스로 신뢰도를 매겨 채택 · 확장 · 조합 · 직접 만들기 중 하나를 권한다. 승인을 받은 뒤 테스트부터 쓰고 구현한다 | 1일차가 하루로 줄어 시연을 뺐다 (2026-10-26). 질문이 나오면 설명만 한다 | 하위 에이전트 여러 개를 동시에 돌려 사용량이 크다. superpowers TDD 스킬이 필요하다. 테스트 주도 개발은 이 과정 범위 밖이다 |
| `/cross-verify` | 같은 문서를 다른 AI(Codex · Antigravity)에게도 묻고, 수치 근거를 원문과 대조해 지어낸 근거를 걸러 낸 뒤 종합한다 | 2일차 3교시 정리 — "한 AI의 답을 다른 AI로 검증한다". 보고서 초안으로 미리 돌린 결과를 보여 준다 | 같은 PC에 다른 에이전트 CLI가 로그인돼 있어야 한다(구독 2개 이상). 패널을 high effort로 불러 교육 상한을 넘는다. 명령이 bash 기준이다. 구독이 둘 이상인 수강생은 수료 후 도전 |
| demo-video | 실제 웹앱을 자동으로 조작 · 녹화해 자막 · 커서 · 줌이 들어간 시연 mp4를 만든다 | 영상 실습을 빼서 시연도 뺐다 (2026-10-26) | Playwright 추가 설치가 필요하다 |

| visual-explainer | 계획 · 구조를 HTML 그림으로 설명한다 | 선택 — `PLAN.md` 를 그림으로 보여 줄 때 | 필수 흐름에 없다 |
