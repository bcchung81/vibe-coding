# 바이브코딩 중급교육 1일차 — 환경설정 (Codex · Claude Code · Antigravity · Windows)

> 교육 당일 공개하는 환경설정 파일입니다. 사전설치(`00_사전안내.md` 3장)를 마친 PC 기준입니다 — Node.js 22 이상, 코드 에이전트 설치, **본인 구독 계정으로 로그인**. Node.js가 없거나 22 미만이면 `setup.ps1` 이 설치합니다.
> 설치는 **`setup.ps1`** 이 하고, 점검·로그인·문제 해결은 **내 코드 에이전트** 가 이 파일의 Part B를 읽고 진행합니다.
> `setup.ps1` 은 고른 에이전트에 맞춰 설정합니다 — Codex · Claude Code · Antigravity (여러 개 가능). 명령이 에이전트마다 다르면 내 에이전트의 것만 봅니다.
> 작업 공간은 모든 PC에서 **`C:\workspace`** 입니다. 강사가 주는 파일과 모든 실습 프로젝트를 이 폴더에 둡니다.
> 기준 환경: **Windows 11 · PowerShell**

## Part A. 사람이 하는 일 (1일차 1교시)

1. **일반 PowerShell 창**(관리자로 실행 아님)에서 사전설치 상태를 확인합니다. 하나라도 안 되면 조교를 부릅니다.
   ```powershell
   node -v
   codex --version; codex login status              # Codex
   claude --version; claude auth status --text      # Claude Code
   ```
   Antigravity는 앱을 열어 로그인된 계정을 확인합니다. 로그인이 안 되어 있으면 `00_사전안내.md` 3-5대로 **구독 계정** 으로 로그인합니다 (API 키 로그인은 쓰지 않습니다).
2. 강사가 준 파일 3개(`setup.ps1` · `00_환경설정.md` · `AGENTS.global.md`)를 **`C:\workspace`** 에 저장합니다.
   - `AGENTS.global.md` 는 공통 규칙의 원본입니다. 스크립트가 고른 에이전트의 전역 위치로 복사합니다. 이름을 `AGENTS.md` 로 바꾸지 않습니다 (작업 공간에 `AGENTS.md` 가 있으면 규칙을 두 번 읽어 토큰을 더 씁니다).
3. 설치 스크립트를 실행합니다.
   ```powershell
   cd C:\workspace
   powershell -ExecutionPolicy Bypass -File .\setup.ps1
   ```
   에이전트를 미리 정해 실행하려면 끝에 `-Agents codex,claude,antigravity` 처럼 붙입니다.

   | 화면에 이게 나오면 | 이렇게 |
   |---|---|
   | `Which AI agents should be set up?` | 구독한 에이전트 번호 입력 (여러 개면 쉼표). **그냥 Enter = 이 PC에서 찾은 에이전트 모두** (`(found)` 표시) |
   | 관리자 확인 창(UAC) | "예". 관리자 권한이 없어 누를 수 없으면 "아니요" — 스크립트가 관리자 권한 없이 다시 시도한다 |
   | `Continue anyway? (y/N)` | 관리자 권한 창에서 실행한 것. Enter로 멈추고, 일반 PowerShell 창에서 다시 실행 |
   | `Git user name` · `GitHub e-mail` | 이름과 GitHub 이메일 입력 (`00_사전안내.md` 2-2 ②에서 확인한 주소) |
   | `LAW_OC` | 인증값(`00_사전안내.md` 2-2 ③) 입력 후 Enter. 글자가 안 보이는 게 정상. 아직 없으면 그냥 Enter |
   | 결과 표에 `WARN` · `FAIL` | 그대로 다음 단계로. 에이전트가 함께 해결한다 |

   결과 표의 상태: `OK` 완료 · `SKIP` 이미 되어 있음 · `WARN` 확인 필요 · `FAIL` 실패

4. **열려 있는 PowerShell · 터미널 창을 모두 닫고**, 새 창에서 내 에이전트를 실행합니다. (바뀐 PATH는 새 창에서만 적용됩니다)

   | 에이전트 | 시작 | 이어서 다시 시작 |
   |---|---|---|
   | Codex | `cd C:\workspace` → `codex` | `codex resume --last` |
   | Claude Code | `cd C:\workspace` → `claude` | `claude --continue` |
   | Antigravity | 앱 → **Open Folder** → `C:\workspace` → 에이전트 창 | 앱을 다시 열고 같은 대화 선택 |

5. 아래 한 줄을 입력합니다.
   ```
   00_환경설정.md 파일을 읽고 Part B를 순서대로 진행해줘
   ```
6. 이후에는 에이전트가 안내하는 것만 하면 됩니다.

   | 이런 게 나오면 | 이렇게 |
   |---|---|
   | 명령 실행 승인 요청 | 명령과 이유를 읽어 보고 허용 |
   | 관리자 확인 창(UAC) | "예". 기관 PC라 막히면 조교를 부른다 |
   | "별도 PowerShell 창에서 실행해 주세요" | 새 PowerShell 창을 열어 안내받은 명령을 직접 입력 (로그인용) |
   | 브라우저 로그인 · 가입 | 직접 처리 후 에이전트 창에 "완료" 입력 |
   | "재시작해 주세요" | `/exit` → 창 모두 닫기 → 새 창 → 4번 표의 **이어서 다시 시작** (Antigravity는 앱을 닫았다 다시 열기) |

## Part B. 에이전트 지시문

> **여기부터는 코드 에이전트(Codex · Claude Code · Antigravity)에게 주는 지시입니다.** 공통 규칙은 전역 규칙 파일을 따른다. 명령이 에이전트마다 다르면 지금 쓰는 에이전트의 것만 실행한다. 설치는 사람이 `setup.ps1` 로 이미 실행했다. 결과를 확인하고, 실패한 항목만 고치고, 계정 로그인을 안내한다.

### B-0. 이 단계의 추가 규칙

1. B-1부터 B-7까지 **순서대로** 진행한다. 단계를 시작할 때 한 줄로 알리고, 확인 명령의 결과로 성공 여부를 보고한다.
2. **`setup.ps1` 이 끝낸 항목은 다시 설치하지 않는다.** `WARN` · `FAIL` 항목만 사용자 승인을 받아 조치한다.
3. **PATH · 실행 정책은 직접 바꾸지 않는다.** 사용자에게 `setup.ps1` 을 다시 실행하게 안내한다 (스크립트가 사용자 PATH와 실행 정책을 고친다).
4. 사람만 할 수 있는 일(계정 가입, 브라우저 로그인, 관리자 승인)은 안내한 뒤 "완료"를 기다린다. 대화형 로그인 명령은 사용자가 **별도 PowerShell 창** 에서 입력하게 한다.
5. 키 · 토큰 · 인증값을 요구하지 않고, 결과 파일에 적지 않는다.

### B-1. 설치 결과 확인

1. 로그에서 결과 줄만 읽어 표로 요약한다. 파일이 없으면 `setup.ps1` 을 실행하지 않은 것이다 → Part A 3번을 안내하고 멈춘다.
   ```powershell
   Select-String -Path setup-log.txt -Pattern ' \| (OK|SKIP|WARN|FAIL) \| '
   ```
2. 모두 `OK` · `SKIP` 이면 B-3으로 간다. `WARN` · `FAIL` 이 있으면 그 항목만 지금 상태를 확인한다 (아래에서 해당 줄만 실행).
   ```powershell
   git --version; python --version; python3 --version; gh --version; vercel.cmd --version; hyperframes.cmd --version
   ffmpeg -version | Select-Object -First 1
   codex mcp list                                   # Codex
   claude mcp list; claude plugin list              # Claude Code
   (Get-Content $HOME\.gemini\config\mcp_config.json -Raw | ConvertFrom-Json).mcpServers.PSObject.Properties.Name   # Antigravity
   Get-ChildItem $HOME\.agents\skills, $HOME\.claude\skills, $HOME\.gemini\config\skills -Name -ErrorAction SilentlyContinue
   Test-Path $HOME\.codex\AGENTS.md, $HOME\.claude\CLAUDE.md, $HOME\.gemini\AGENTS.md
   Select-String default_subagent_ $HOME\.codex\config.toml   # Codex
   git -C C:\workspace\report-harness log -1 --oneline; git -C C:\workspace\hyperframes-skills log -1 --oneline
   ```

| `Codex MCP kordoc` | `codex mcp add kordoc '--' cmd /c npx -y kordoc@4.15.3 mcp` (report-harness가 검증한 판으로 고정) |
| `Codex MCP korean-law` · `Claude MCP korean-law` · `Antigravity MCP korean-law` | 인증값이 들어가므로 직접 하지 않는다. 사용자에게 별도 PowerShell 창에서 `setup.ps1` 을 다시 실행하게 한다 (`LAW_OC` 만 다시 묻는다). 아직 `LAW_OC` 가 없으면 "korean-law 미등록"으로 기록 |
| `Claude MCP …` · `Antigravity MCP` · `Claude plugin report-harness` | `setup.ps1` 다시 실행 |
| `impeccable (…)` | `npx.cmd -y impeccable install -y --providers=codex --scope=global` (Claude Code는 `--providers=claude`. `-y` 가 두 번 — 앞은 npx, 뒤는 impeccable 질문 건너뛰기) |
| `kca-report-hwpx (…)` · `humanizer (…)` · `HyperFrames skills (…)` | `C:\workspace\report-harness` · `C:\workspace\hyperframes-skills\skills` 가 있는지 확인하고 `setup.ps1` 다시 실행 |
| `think (…)` | `setup.ps1` 다시 실행 |
| `Codex rules` | `C:\workspace` 에 `AGENTS.global.md` 가 있는지 확인하고 `setup.ps1` 다시 실행 |
| `Claude rules` · `Antigravity rules` (`WARN`) | 사용자의 개인 전역 규칙 파일을 보존한 것이다. 합칠지는 사용자에게 묻는다 |
| `Sub-agent reasoning` (`WARN`) | 사용자 승인을 받아 `$HOME\.codex\config.toml` 의 `[agents]` 표에 `default_subagent_model = "gpt-6-sol"` · `default_subagent_reasoning_effort = "medium"` 을 넣는다 (이미 다른 값이면 이 값으로 바꾼다) |
| `Git user` | 사용자에게 이름과 GitHub 가입 이메일을 묻고 `git config --global user.name` · `user.email` 로 설정 |

- **재시작 체크포인트** — 새로 설치한 도구는 지금 세션에서 보이지 않는다. 확인 명령이 실패하면 재시작(`/exit` → 창 모두 닫기 → 새 창 → Part A 4번 표의 **이어서 다시 시작**)을 안내하고, 돌아오면 B-2 확인부터 이어 간다.
- Codex: `codex mcp get kordoc` 으로 명령이 `cmd` · 인자가 `/c npx -y kordoc@4.15.3 mcp` 인지 확인한다. `--` 가 인자에 섞여 있으면 `codex mcp remove kordoc` 후 다시 등록한다. Claude Code는 `claude mcp get kordoc`.
- impeccable 사용 통계 전송을 끄려면 `npx.cmd -y impeccable telemetry off`, HyperFrames는 `setx HYPERFRAMES_NO_TELEMETRY 1`. 기관 정책상 필요하면 사용자에게 물어 실행한다.

### B-3. GitHub — CLI 로그인

1. 사용자에게 GitHub 계정이 있는지 묻는다. 없으면 가입 페이지를 열어 주고(`start https://github.com/signup`), 가입과 이메일 인증을 마치면 "완료"를 입력하게 한다.
2. 사용자에게 **별도 PowerShell 창** 에서 아래를 입력하게 안내한다. 화면의 8자리 코드를 브라우저에 입력하고 **Authorize** 를 누르면 된다.
   ```powershell
   gh auth login -h github.com -p https -w
   ```
   브라우저가 안 열리면 https://github.com/login/device 를 직접 열게 한다.
3. "완료"를 받으면 git이 GitHub 로그인 정보를 쓰도록 연결한다: `gh auth setup-git`

**확인**: `gh auth status` → `Logged in to github.com account <아이디>`

### B-4. Vercel — 계정 · CLI 로그인

1. 계정이 없으면 https://vercel.com/signup 을 열어 주고 안내한다: 요금제 **Hobby** → **Continue with GitHub** (B-3의 계정 사용).
2. 사용자에게 **별도 PowerShell 창** 에서 `vercel.cmd login` 을 입력하게 안내한다. 브라우저에서 승인하면 된다.

**확인**: `vercel.cmd whoami` → 사용자 이름 출력

### B-5. Supabase — 계정 · CLI 로그인

1. 계정이 없으면 https://supabase.com/dashboard/sign-up 을 열어 주고 안내한다.
   - **Continue with GitHub** 로 가입한다. Organization 이름은 본인 이름, 요금제는 **Free**.
   - **프로젝트는 지금 만들지 않는다** (도전과제에서 만든다. Free는 활성 프로젝트 2개까지).
2. CLI는 설치하지 않고 **npx로 쓴다**: `supabase` 명령은 `npx.cmd -y supabase@latest` 로 바꿔 실행한다.
3. 사용자에게 **별도 PowerShell 창** 에서 아래를 입력하게 안내한다. 브라우저에서 승인한 뒤, 화면의 인증 코드를 터미널에 입력하면 된다.
   ```powershell
   npx.cmd -y supabase@latest login
   ```

**확인**: `npx.cmd -y supabase@latest projects list` → 목록이 비어 있어도 오류가 없으면 성공

### B-6. 결과 기록

현재 폴더에 `환경점검결과.md` 를 만들고 사용자에게도 표로 보여 준다. 이 파일이 **1교시 제출물** 이다.

- 점검 일시 · Windows 버전 · 실행 정책 · 작업 공간(`C:\workspace`) 권한
- 도구별 버전: 사용 에이전트 · Git · Node.js · Python · GitHub CLI · Vercel CLI · Supabase CLI · HyperFrames CLI · FFmpeg
- 로그인 상태: 에이전트(구독 / API 키) · GitHub 아이디 · Vercel 사용자 이름 · Supabase
- 설정한 에이전트 · MCP 등록 상태 · 스킬(impeccable · kca-report-hwpx · humanizer · think · HyperFrames) · 에이전트 규칙(전역 규칙 파일 · Codex는 하위 에이전트 상한)
- 교육 저장소(report-harness · hyperframes-skills) 위치와 최신 커밋
- `setup.ps1` 에서 실패했다가 B-2에서 고친 항목, 끝내 실패·건너뛴 항목과 그 이유

**토큰 · 비밀번호 · 인증값 · 이메일 주소는 적지 않는다.**

### B-7. 재시작 · 동작 확인

MCP · 스킬 · 전역 규칙은 **새 세션에서 불러와진다.**

1. 사용자에게 재시작(`/exit` → 새 창 → Part A 4번 표의 **이어서 다시 시작**)을 안내한다.
2. 사용자가 직접 확인한다.

   | 에이전트 | MCP (sequential-thinking · kordoc · korean-law) | 스킬 · 보고서 도구 |
   |---|---|---|
   | Codex | `/mcp` | `/skills` → impeccable · kca-report-hwpx · humanizer · think · hyperframes |
   | Claude Code | `/mcp` | `/skills` → impeccable · think · hyperframes · `/plugin` → report-harness |
   | Antigravity | Settings → Customizations → Installed MCP Servers | 에이전트에게 "쓸 수 있는 스킬 이름만 말해줘" |
3. 에이전트가 직접 시험한다. MCP 연결은 `/mcp` 표시로 확인하고, 문서를 실제로 읽는 시험은 하지 않는다 (토큰 절약).
   - **korean-law**: "전파법"을 한 번 검색해 법령명 1건만 보여 준다. 미등록이면 건너뛴다.
   - **전역 규칙**: 지금 적용 중인 공통 규칙의 장 제목을 한 줄로 말한다. 말하지 못하면 전역 규칙 파일(Codex `~\.codex\AGENTS.md` · Claude Code `~\.claude\CLAUDE.md` · Antigravity `~\.gemini\AGENTS.md`)이 읽히지 않은 것이다.
4. `환경점검결과.md` 에 동작 확인 결과를 덧붙이고, 마지막에 이렇게 알린다: **"환경설정이 끝났습니다. 이 파일을 강사에게 제출해 주세요."**

## 부록. 문제 해결

| 증상 | 조치 |
|---|---|
| `setup.ps1` 이 실행되지 않는다 · 보안 경고 | 실행 명령을 `powershell -ExecutionPolicy Bypass -File .\setup.ps1` 그대로 입력했는지 확인. "디지털 서명되지 않았습니다"(not digitally signed)면 인터넷에서 받은 파일 표시 때문이다 → `Unblock-File .\setup.ps1` 후 다시. 그래도 "그룹 정책" 메시지면 전산부서 |
| `PowerShell runs in ConstrainedLanguage mode` | 기관 보안 정책(AppLocker · WDAC)이 스크립트를 제한한 PC다. 우회하지 말고 전산부서 |
| `Continue anyway? (y/N)` | 관리자 권한 창에서 실행한 것. Enter로 멈추고 일반 PowerShell 창에서 다시 실행 |
| `Cannot write to C:\workspace` | 기관 PC가 C 드라이브 최상위 폴더 만들기를 막았거나, 다른 계정이 만든 폴더라 쓸 수 없는 경우 → 전산부서 |
| `Pre-course setup is not finished` | 결과 표의 `FAIL` 항목을 `00_사전안내.md` 3장에서 다시 → 조교 |
| `Execution policy  FAIL ... Group Policy` | 기관 정책으로 막힘 → 전산부서에 RemoteSigned 허용 요청. 그동안 `npm.cmd` · `npx.cmd` 로 진행 |
| 설치했는데 `명령을 찾을 수 없습니다` | PowerShell · 터미널 창을 모두 닫고 새 창. 그래도 안 되면 `setup.ps1` 다시 실행(PATH 보정) → 그래도 안 되면 로그아웃 후 다시 로그인 |
| `npm.ps1 파일을 로드할 수 없습니다` | 실행 정책 미설정 → `setup.ps1` 다시 실행 (실행 정책을 고친다) |
| 에이전트가 로그인 안 됨 · API 키로 로그인됨 | 별도 창에서 Codex `codex logout` → `codex login` / Claude Code `claude auth logout` → `claude auth login` → **구독 계정** 으로 로그인 |
| Claude Code가 API 키를 쓸지 묻는다 | No (구독으로 쓴다) |
| 사용량 한도에 걸렸다 | 남은 한도와 풀리는 시각 확인 — Codex `/status` · Claude Code `/usage` · Antigravity 설정 화면. **API 키 · 추가 결제(크레딧)로 넘기지 않는다.** 강사에게 알린다 |
| Windows 샌드박스 설정이 실패한다 (Codex) | 관리자 승인 창을 거절했거나 기관 정책으로 막힌 경우. 조교를 부른다 |
| 명령마다 승인 요청이 뜬다 | 정상이다. 설치·로그인 확인은 인터넷과 폴더 밖 쓰기가 필요하다. 명령을 읽고 허용 |
| `python` · `python3` 이 Microsoft Store를 연다 | PowerShell 창을 모두 닫고 새 창에서 다시 확인. 그래도 안 되면 `setup.ps1` 다시 실행 (Python 폴더를 PATH 맨 앞에 두고 `python3` 를 만든다) |
| `winget` 이 없다 | 스크립트가 먼저 등록을 시도한다. 그래도 없으면 Microsoft Store에서 "앱 설치 관리자" 업데이트 후 `setup.ps1` 다시 실행 |
| `SELF_SIGNED_CERT_IN_CHAIN` · `UNABLE_TO_GET_ISSUER_CERT` | 인터넷망 PC인지 확인. 사내 프록시면 담당자에게 문의. **`strict-ssl false` 로 우회하지 않는다** |
| `/mcp` 에서 MCP가 실패로 보인다 | `node -v` 가 v22 이상인지, `codex mcp get <이름>` · `claude mcp get <이름>` 의 명령이 `cmd` · 인자가 `/c npx ...` 인지 확인. 첫 실행은 패키지를 내려받느라 늦을 수 있으니 재시작 후 한 번 더 |
| `Repo … FAIL  git clone failed` | github.com 접속이 막혔는지 확인(보안 프로그램·프록시) → 전산부서. 열리면 `setup.ps1` 다시 실행 |
| GitHub 로그인 브라우저가 안 열린다 | https://github.com/login/device 를 직접 열어 코드 입력 |
| Supabase 프로젝트를 더 못 만든다 | Free는 활성 프로젝트 2개까지. 다 쓴 실습 프로젝트를 일시정지하거나 삭제 |
| 교육이 끝났다 | 공용 PC면 반드시 로그아웃 — Codex `codex logout` · Claude Code `claude auth logout` · Antigravity 앱에서 로그아웃 |
