# AGENTS.md

바이브코딩 중급교육 공통 규칙 (Codex · Claude Code · Antigravity). 프로젝트 폴더에 `AGENTS.md` 가 따로 있으면 함께 따른다.

## 1. 사용자와 환경

- 사용자는 개발자가 아니다. 쉬운 한국어로 짧게 답한다. 전문용어는 처음 한 번만 풀어 준다.
- Windows 11 · PowerShell. 한글·공백 경로는 따옴표로 감싼다.
- 작업 공간은 `C:\workspace` 다. 새 프로젝트는 그 아래 폴더로 만들고, 작업 공간 밖에는 파일을 만들지 않는다. 예외: 사용자가 시킨 스킬 설치 · 만들기는 전역 스킬 폴더(Codex `~\.agents\skills` · Claude Code `~\.claude\skills` · Antigravity `~\.gemini\config\skills`)에 둔다.
- `npm` · `npx` · `vercel` 대신 `npm.cmd` · `npx.cmd` · `vercel.cmd` 를 쓴다 (PowerShell 실행 정책에 막히지 않는다).
- 스킬 문서의 bash 명령(`$VAR` · `/tmp`)은 PowerShell에 맞게 바꿔 실행한다. 임시 파일은 `/tmp` 대신 현재 프로젝트 안 `scratchpad-tmp/` 에 둔다.

## 2. 코딩 전에

- 가정은 한 줄로 밝힌다. 해석이 갈리거나 불분명하면 멈추고 묻는다. 질문은 한 번에 2개, 선택지는 3개까지.
- 더 단순한 방법이 있으면 말한다.

## 3. 단순하게

- 요청한 것만 만든다. 요청하지 않은 기능·설정·추상화, 일어날 수 없는 상황의 오류 처리는 넣지 않는다.
- 길게 썼으면 더 짧게 쓸 수 있는지 다시 본다.

## 4. 필요한 곳만 고친다

- 요청과 관계없는 코드·주석·서식은 건드리지 않는다. 기존 스타일을 따른다.
- 내 변경으로 안 쓰게 된 것만 지운다. 원래 있던 안 쓰는 코드는 알려만 준다.

## 5. 확인은 가볍게

- 작업 전에 성공 기준을 한 줄로 정한다. 여러 단계면 `1. [단계] → 확인: [방법]` 형식으로 짧게 계획을 보인다.
- 확인은 가장 가벼운 방법 한 번: 화면은 사용자가 브라우저로 보게 하고, 코드는 `npm.cmd run build` 나 해당 함수만 실행한다.
- 테스트 코드는 핵심 로직(`lib/`)이거나 사용자가 요청할 때만 쓴다.
- 같은 문제로 2번 실패하면 멈추고 오류 원문 · 원인 추정 · 대안을 보고한다.

## 6. 토큰 아끼기

- 필요한 부분만 읽는다. `Select-String` · `Get-ChildItem` 으로 위치를 먼저 찾는다.
- 읽지 않는다: `node_modules` · `.next` · `package-lock.json` · 빌드 결과물 · 이미지·영상.
- 긴 출력(설치·빌드 로그)은 끝부분만 본다: `... | Select-Object -Last 30`
- 이미 읽은 파일을 통째로 다시 읽거나, 고친 파일 전체를 다시 보여 주지 않는다.
- hwpx · pdf 같은 큰 문서는 필요한 쪽·표만 읽는다.
- MCP · 스킬은 필요할 때만 쓴다. sequential-thinking 과 impeccable 은 사용자가 요청할 때만 쓴다.
- 개발 서버(`npm.cmd run dev`)는 한 번 띄워 두고 다시 쓴다.

## 7. 난이도와 모델 설정

- 작업 요청이면 첫 줄에 난이도를 밝힌다. 예: `난이도: 보통 — 화면 하나 추가`
  - 쉬움 (설명 · 문구 수정 · 명령 하나): 바로 처리
  - 보통 (화면·기능 하나, 원인이 보이는 오류): 짧은 계획 후 처리
  - 어려움 (여러 파일 구조 변경 · 설계, 원인 모르는 오류): 계획을 먼저 승인받고 처리
- **교육 중에는 아래 상한 이하로만 쓴다.** 교육 동안 본인 구독 한도가 버티게 하기 위해서다. 난이도와 관계없이 같다.

| 에이전트 | 상한 (= 기본 설정) | 더 낮게 써도 되는 것 | 바꾸는 곳 |
|---|---|---|---|
| Codex | `gpt-6-sol` · `medium` | effort `low`, 모델 `gpt-6-luna` | `/model` |
| Claude Code | `sonnet` · `medium` | effort `low`, 모델 `haiku` | `/model sonnet` · `/effort medium` |
| Antigravity | Gemini 3.8 Flash · Medium | Low · Fast | 입력창 아래 모델 선택 메뉴 |

- 상한을 넘는 것은 쓰지 않는다. Codex `gpt-6.1-sol` · `gpt-6-astra` · `high` 이상 · Ultra / Claude Code `opus` · `opusplan` · `fable` · `best` · `high` 이상 / Antigravity Gemini 4 Argon · High · Claude · GPT 모델.
- 모델은 사용자가 바꾼다. 첫 응답에서 지금 설정이 상한보다 높으면 (예: Claude Code가 Opus로 시작) 바꾸는 명령을 한 줄 안내하고 "계속"을 기다린다.
- 어려움도 모델 · effort를 올리지 않는다. 계획을 먼저 승인받고, 작은 단계로 나눠 단계마다 확인한다.
- 사용자가 더 높은 모델 · effort를 원하면 교육 중에는 상한 안에서 한다고 알리고, 필요하면 강사에게 말하게 한다.
- 상한 모델이 `/model` 목록에 없으면 상한보다 낮은 것 중 가장 가까운 것을 쓰고 알린다.
- 하위 에이전트(깊은 추론)는 토큰을 많이 쓴다. **같은 문제로 2번 실패했거나, 사용자가 "깊게 분석해 줘"라고 할 때만** 쓴다. 하위 에이전트도 상한을 지킨다: Codex `gpt-6-sol` · `medium`, Claude Code `sonnet` · `medium`, Antigravity `model: flash`. 맡길 때 사용자에게 한 줄로 알리고 이렇게 지시한다:
  `원인 분석과 수정 계획만. 파일 수정 금지. 돌려줄 것: 원인과 근거, 단계별 계획(단계마다 확인 방법), 확인 못 한 가정. 비밀값 출력 금지.`
- 수정은 이 세션에서 사용자 승인을 받아 한다.

## 8. 보안과 권한

- 키 · 토큰 · 비밀번호 · 인증값은 `.env.local` 에만 둔다. 코드 · 커밋 · 대화창 · 결과 파일에 쓰지 않고, 붙여넣으라고 하지 않는다. `.env*` 는 `.gitignore` 에 넣고 커밋 전에 확인한다.
- AI 구독 계정(ChatGPT · Claude · Google) 정보나 API 키를 웹앱에 넣지 않는다.
- 사용자는 본인 구독으로 쓴다. 사용 한도에 걸리면 알리고 기다린다. API 키 로그인 · 추가 결제(크레딧)로 우회하지 않는다.
- 공개자료만 쓴다. 내부자료·개인정보로 보이면 쓰기 전에 묻는다.
- 샌드박스를 끄거나 전체 권한을 요구하지 않는다. 작업 폴더 밖 대량 삭제, 시스템 설정(PATH 영구 변경 · 실행 정책 · 레지스트리) 변경은 하지 않는다.
- 대화형 로그인은 사용자가 별도 PowerShell 창에서 하게 안내한다.
