---
name: deck-export
description: 덱을 영상(mp4)으로 내보낸다 — t를 1/30초씩 넣어 Edge로 한 장씩 찍고 FFmpeg로 묶는다. 원하면 GIF도. 사용자가 deck-export 스킬을 부를 때만 쓴다.
---

녹화가 아니라 프레임 렌더다. 느린 PC는 오래 걸릴 뿐 영상은 매끈하다.

1. 사용자의 말을 명령으로 바꾼다.

| 사용자가 말한 것 | 붙일 것 |
|---|---|
| 어느 장 (예: 표지 · 3장 · 마지막 장) | `--slides 1,3,6` — 빼면 모든 장 |
| 길이 (예: 30초) | `--sec 10` — 장마다 초 = 길이 ÷ 장 수. 빼면 장마다 `data-sec` |
| "장마다 8초" | `--sec 8` |
| GIF | `--gif` |
| 고화질 · 1080 | `--hd` (기본 1280×720 — 2배쯤 오래 걸린다) |

2. 실행 전에 한 줄로 알린다: 몇 장 · 몇 초 · 걸릴 시간(업무 노트북 30초 영상 3~5분 예상). **렌더 중에는 창을 닫지 말라**고 말한다.
3. 실행한다 (개발 서버가 꺼져 있어도 된다 — 스스로 빌드해서 찍는다):
   ```
   npm.cmd run export -- --slides 1,3,6 --sec 10
   ```
4. 막히면:

| 메시지 | 할 일 |
|---|---|
| Edge를 찾지 못했습니다 | Edge 설치 여부를 사용자에게 묻는다. 다른 브라우저는 `$env:BROWSER` 에 실행 파일 경로를 넣고 다시 |
| FFmpeg를 찾지 못했습니다 | 새 창에서 `ffmpeg -version` 을 해 보게 하고, 안 되면 조교를 부르게 한다 |
| 덱 오류: … | 그 오류 원문으로 원인을 찾아 고친다. 장면이 `Math.random` · `Date.now` 를 쓰면 t로 바꾼다 |

5. 끝나면 `out\deck.mp4`(와 `out\deck.gif`) 경로 · 크기 · 걸린 시간을 보고하고, 사용자에게 파일을 열어 끊김 없이 재생되는지 보라고 말한다. 길거나 빠르면 `--sec` 를 바꿔 다시 한다.
