사용자가 준 것을 보고 아래 셋 중 **하나만** 한다. 무엇을 할지 한 줄로 먼저 말한다.

| 사용자가 준 것 | 할 일 |
|---|---|
| 아무것도 없음 · "다음 단계" | A. 다음 단계 만들기 |
| 오류 원문 · "안 돼요" · "이상해요" | B. 고치기 |
| "배포 전 점검" · "배포" | C. 배포 전 점검 |

`PRD.md` · `PLAN.md` 가 없으면 멈추고 `/vibe-plan` 부터 하라고 말한다.

## A. 다음 단계 만들기

`PLAN.md` 에서 상태가 `[ ]` 인 첫 단계 **하나만** 한다.

1. `PRD.md` · `PLAN.md` · 고른 주제 카드(`topics/`)를 읽는다.
2. 그 단계만 구현한다. 다음 단계로 넘어가지 않는다.
3. 확인: `npm.cmd run build` 가 통과하는지 보고, 사용자에게 브라우저에서 볼 것(http://localhost:3000 · 그 단계의 완료 기준)을 알려 준다. 개발 서버가 꺼져 있으면 `npm.cmd run dev` 를 띄운다.
4. 통과하면 `PLAN.md` 의 그 단계를 `[x]` 로 바꾸고, 확인한 방법을 한 줄 적는다.
5. 실제 API 단계일 때:
   - 키는 `.env.local` 의 `DATA_GO_KR_KEY` (Decoding 키)만 쓴다. 값을 묻거나 출력하지 않는다. 없으면 `시작하기.md` 3번대로 사용자가 직접 넣게 안내하고 기다린다.
   - 요청 주소 · 파라미터 · 응답 항목은 주제 카드의 표를 따른다. 파라미터는 `URLSearchParams` 로 조립한다.
   - 호출이 실패하면 `data/snapshot.json` 을 대신 돌려주고 화면에 "예시 데이터"라고 표시한다. 오류 원문은 화면에 보내지 않는다.
6. 모든 단계가 `[x]` 이면 "다음: `/vibe-design` 으로 화면 다듬기, 또는 `/vibe-develop 배포 전 점검`"을 말한다.

## B. 고치기

고치기 전에 진단부터 한다.

1. 오류 **원문**이 없으면 그대로 붙여 넣어 달라고 한다. 요약 말고 원문(터미널 출력 · 브라우저 화면의 글자)이다.
2. 원인 가설 3개와 각각을 확인하는 방법을 먼저 말한다. 주제 카드의 "막히는 곳"에 비슷한 것이 있으면 그것부터 본다. 원인이 잘 안 보이면 `think` 스킬(sequential-thinking MCP)로 단계별로 따진다.
3. 가능성이 높은 것부터 확인하고, 한 번에 **하나만** 고친다. 고친 뒤 같은 방법으로 다시 확인한다.
4. 같은 문제로 두 번 실패하면 멈추고, 다른 접근 하나를 제안해 사용자가 고르게 한다.
5. 대화가 길어져 헤매면, 새 세션을 열고 `PLAN.md` 부터 다시 읽히라고 안내한다.
6. 오류 원문에 키 값이 섞여 있으면 그 값은 다시 적지 않는다.

## C. 배포 전 점검

세 가지를 점검하고 표로 보고한다. 배포는 하지 않는다 — 사용자가 시킬 때 한다.

| 점검 | 확인 방법 | 통과 |
|---|---|---|
| 1. 키가 git에 없나 | `git check-ignore .env.local` 이 `.env.local` 을 출력한다 · `git ls-files` 에 `.env` 로 시작하는 파일이 없다(`.env.example` 만 예외) · 코드에 키처럼 긴 문자열이 없다 | 셋 다 |
| 2. 키 없이도 빌드되나 | 키를 빌드할 때가 아니라 요청이 올 때 서버 라우트 안에서 읽는지 코드를 본다 → `npm.cmd run build` | 빌드 통과 |
| 3. 오류 원문이 화면에 안 보이나 | 서버 라우트의 실패 처리와 화면의 오류 표시를 본다. 응답에 오류 원문 · 키 · 요청 주소가 담기지 않는다 | 예시 데이터 · 사용자 문구만 |

- 그 밖에 `vercel.json` 의 지역이 `icn1` 인지 본다.
- 하나라도 통과하지 못하면 고칠 곳만 말하고, 고칠지 사용자에게 묻는다.
- 모두 통과하면 다음을 말한다: "다음: `이 폴더를 Vercel 프로덕션으로 배포해줘. 환경변수는 내가 직접 넣을 테니 넣을 이름만 알려줘` — 키 값은 본인이 별도 PowerShell 창에서 `vercel.cmd env add DATA_GO_KR_KEY production` 으로 넣는다". 배포할 때 Vercel CLI는 `vercel.cmd` 로 부른다.
