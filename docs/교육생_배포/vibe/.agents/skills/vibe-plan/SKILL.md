기획을 한 번에 한다 — 인터뷰 → `PRD.md` → `PLAN.md`. 코드는 고치지 않는다.

## 1. 인터뷰 → PRD.md

1. 주제: 사용자가 말한 주제 번호(예: `02`)로 `topics/` 에서 카드를 찾는다. 번호가 없으면 `topics/` 의 번호 · 제목 목록을 보여 주고 고르게 한다.
   - 예시 데이터: `data/<번호>.json` 이 있으면 `data/snapshot.json` 으로 복사한다. `data/snapshot.json` 에 이미 `items` 가 있으면 덮기 전에 묻는다.
2. `PRD.md` 가 이미 있으면 이 절을 건너뛰고 2로 간다. 사용자가 다시 쓰라고 할 때만 새로 쓴다.
3. 카드를 읽고, 만들 앱에 대해 질문을 **5개 이하로 하나씩** 묻는다. 예: 누가 언제 쓰나 · 첫 화면에 꼭 보일 것 · 고르는 조건(지역 · 품목 등) · 보여 주는 방식(카드 · 표) · 빼도 되는 것.
4. 사용자가 범위를 못 정하면 `think` 스킬(sequential-thinking MCP — `setup.ps1` 이 전역에 설치)로 "이 카드로 오늘 70분 안에 만들 수 있는 화면 범위"를 단계별로 따져 제안한다. `think` 가 없으면 같은 질문을 직접 따진다.
5. 답을 모아 `PRD.md` 를 쓴다.

| 칸 | 내용 |
|---|---|
| 주제 | 카드 번호 · 제목 (예: `02 자격시험 공지 모아보기`) |
| 한 줄 소개 | 누가 · 무엇을 · 왜 |
| 화면 | 한 화면에 보일 것, 위에서 아래 순서로 |
| 데이터 | 카드의 API · 쓸 응답 항목 · 고르는 조건 |
| 완료 기준 | 눈으로 확인할 수 있는 문장 3개 (카드의 "완료 기준 예시" 참고) |
| 나중에 | 카드의 "향후 고도화" 중 사용자가 원한 것 — 이번에는 만들지 않는다 |

처음 데이터는 `data/snapshot.json` 이다. 실제 API 연결은 `PLAN.md` 의 마지막 단계에서 한다.

## 2. PLAN.md

1. 화면 단계는 **4개 이하**다. 단계마다 할 일 한 줄과, 브라우저에서 눈으로 확인하는 **완료 기준**을 적는다.
   - 좋은 완료 기준: "첫 화면에 예시 데이터 5건이 카드로 보이고, 지역을 바꾸면 2건으로 줄어든다"
   - 나쁜 완료 기준: "화면 완성"
2. 1단계는 보통 "서버 라우트 `/api/data` 가 `data/snapshot.json` 을 돌려주고, 화면에 목록이 보인다"이다.
3. 맨 끝에 **실제 API 단계**를 하나 따로 적는다: "같은 서버 라우트가 실제 API를 부른다 (키는 `.env.local` 의 `DATA_GO_KR_KEY`)". 완료 기준에 "호출이 실패하면 스냅샷이 대신 보이고 '예시 데이터'라고 표시된다"를 넣는다.
4. 형식: 단계마다 `## 1단계 — 제목`, 할 일, 완료 기준, 상태 `[ ]`.
5. 이미 `PLAN.md` 가 있고 사용자가 "향후 고도화"를 하나 더 하자고 하면, 기존 단계는 그대로 두고 맨 끝에 단계 하나를 덧붙인다.

## 3. 끝나면

`PRD.md` 요약 3줄과 단계 목록을 보여 주고 "다음: `vibe-develop 스킬로 다음 단계 해줘`" 을 말한다.
