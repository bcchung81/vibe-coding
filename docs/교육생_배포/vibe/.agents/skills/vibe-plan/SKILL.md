---

`PRD.md` 를 읽고 구현 계획 `PLAN.md` 를 쓴다. 코드는 아직 고치지 않는다.

1. `PRD.md` 가 없으면 멈추고 `/vibe-prd` 부터 하라고 말한다.
2. 화면 단계는 **4개 이하**다. 단계마다 할 일 한 줄과, 브라우저에서 눈으로 확인하는 **완료 기준**을 적는다.
   - 좋은 완료 기준: "첫 화면에 예시 데이터 5건이 카드로 보이고, 지역을 바꾸면 2건으로 줄어든다"
   - 나쁜 완료 기준: "화면 완성"
3. 1단계는 보통 "서버 라우트 `/api/data` 가 `data/snapshot.json` 을 돌려주고, 화면에 목록이 보인다"이다.
4. 맨 끝에 **실제 API 단계**를 하나 따로 적는다: "같은 서버 라우트가 실제 API를 부른다 (키는 `.env.local` 의 `DATA_GO_KR_KEY`)". 완료 기준에 "호출이 실패하면 스냅샷이 대신 보이고 '예시 데이터'라고 표시된다"를 넣는다.
5. 형식: 단계마다 `## 1단계 — 제목`, 할 일, 완료 기준, 상태 `[ ]`.
6. 끝나면 단계 목록을 보여 주고 "다음: `/vibe-step`" 을 말한다.
