description: 오류 원문으로 원인 가설 3개와 확인 방법을 먼저 세우고 하나씩 고친다. 사용자가 /vibe-fix 를 치거나 vibe-fix 스킬을 부를 때만 쓴다.
---

막혔을 때 고치기 전에 진단부터 한다.

1. 오류 **원문**이 없으면 그대로 붙여 넣어 달라고 한다. 요약 말고 원문(터미널 출력 · 브라우저 화면의 글자)이다.
2. 원인 가설 3개와 각각을 확인하는 방법을 먼저 말한다. 주제 카드의 "막히는 곳"에 비슷한 것이 있으면 그것부터 본다.
3. 가능성이 높은 것부터 확인하고, 한 번에 **하나만** 고친다. 고친 뒤 같은 방법으로 다시 확인한다.
4. 같은 문제로 두 번 실패하면 멈추고, 다른 접근 하나를 제안해 사용자가 고르게 한다.
5. 대화가 길어져 헤매면, 새 세션을 열고 `PLAN.md` 부터 다시 읽히라고 안내한다.
6. 오류 원문에 키 값이 섞여 있으면 그 값은 다시 적지 않는다.
