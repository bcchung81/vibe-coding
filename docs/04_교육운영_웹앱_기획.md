## 1. 목적 → 기능

| 목적 | 기능 | 화면 | 단계 |

| ① 사전 수요조사 | 로그인한 수강생이 10문항에 답한다(한 사람에 하나, 다시 내면 바뀐다). 1번 답에 따라 5번 · 7번을 묻는다. 결과는 문항별 그래프로 함께 본다 — 집계만 공개, 서술형 · 기타 답은 강사 화면에서만 이름 없이 | `/survey/answer` · `/survey` | 2026-10-27 |

| ③ 내 사이트 등록 | 사이트 주소 · 앱 이름 · 한 줄 소개. 저장하면 서버가 첫 화면을 찍는다 | `/me` | S2 · S3 |

| `/survey/answer` | 사전 수요조사 답하기 · 고치기. 남은 필수 문항 수를 맨 위 제목이 센다 | 로그인한 수강생 |

| 권한 | 메뉴 | 오른쪽 끝 |
|---|---|---|
| 둘러보기 | 갤러리 · 자료 · 웹앱 주제 · 수요조사(결과) | 로그인 |

## 4. 로그인과 권한

- **공개 범위(오픈형):** 홈 · 문서 · 갤러리는 누구나 본다. 내 사이트 등록과 좋아요만 로그인이 필요하다. 갤러리에 이름 · 팀이 공개되므로 명단에는 공개해도 되는 표기만 넣는다.
- **수강생:** 공통 PIN 4자리(`COURSE_PIN`) → 내 이름(팀) 고르기. 개인 PIN이 없어 따로 정하거나 초기화할 일이 없다. 같은 곳(IP)에서 10분에 30번 틀리면 잠시 막는다 — 강의실은 IP 하나를 같이 쓰므로 넉넉하게 잡았다. PIN을 맞힌 사람만 명단을 볼 수 있다.
- **알고 쓰는 약점:** PIN을 아는 사람은 다른 사람 이름으로 들어갈 수 있다. 교육장 안에서만 쓰는 값이라 받아들이고, 이상하면 관리 화면에서 프로젝트를 고친다.
- **관리자(강사 · 조교):** 관리 PIN 4자리(`ADMIN_PASSWORD`, 공통 PIN과 다른 값, 2026-10-27). 4자리라 더 세게 막는다 — 같은 곳에서 10분에 10번, 모든 곳 합쳐 1시간에 50번 틀리면 막는다(`lib/pin-limit.ts`). 로그인 화면(`/login`)에서도 관리 PIN을 받는다 — 거기서 틀린 것은 공통 PIN 실패로 세되, 그 수가 관리 PIN 기준을 넘으면 로그인 화면은 관리 PIN을 받지 않고 `/admin` 에서만 받는다. 누가 일부러 막히게 하면 Vercel에서 값을 바꾸고 다시 배포한다. '관리' 메뉴는 관리자에게만 보인다.
- **세션:** `SESSION_SECRET` 으로 서명한 쿠키.
- **권한 확인:** `/me` · `/survey/answer` · `/admin` 페이지가 쿠키를 읽어 로그인 안 한 사람을 돌려보내고, 저장하는 서버 함수(`app/actions.ts`)가 쿠키 · PIN을 다시 확인한다. 메뉴를 숨기는 것은 보기 편하게 하려는 것이고 막는 일은 페이지와 서버 함수가 한다. `proxy.ts` 는 쓰지 않는다 — 막을 페이지가 셋뿐이라 페이지에서 확인하는 쪽이 더 단순하고 보안은 같다 (2026-10-26).

## 5. 데이터

| 표 | 내용 |
|---|---|
| `students` | 이름 · 팀 · 고른 웹앱 주제 |
| `projects` | 앱 이름 · 한 줄 소개 · 사이트 주소 · 캡처 주소와 상태 |
| `likes` | 누가 어느 프로젝트에 좋아요를 눌렀는지. 한 사람이 한 프로젝트에 한 번, 자기 것은 안 됨 |
| `pin_failures` | 틀린 PIN의 종류(공통 · 관리) · IP · 시각. 하루 지나면 지운다 |
| `survey_responses` | 수요조사 답(문항 번호 → 고른 선택지 · 기타 · 서술). 수강생 한 명에 한 줄, 다시 내면 바뀐다. 명단에서 지우면 같이 지워진다. 결과 화면은 명단 순서가 아닌 순서로 읽어 서술형 답이 누구 것인지 드러나지 않게 한다 |

- 표 정의: `db/schema.sql`. 추천 순위는 `lib/gallery.ts`, 주소 검사는 `lib/site-url.ts`, 명단 붙여넣기 읽기 · 줄 판정은 `lib/roster.ts`, PIN 잠금 기준은 `lib/pin-limit.ts`, 수요조사 문항 · 답 검사 · 집계는 `lib/survey.ts`, 쿠키 서명은 `lib/session.ts`, 주제 1위 계산은 `lib/topic-counts.ts` (모두 테스트 있음). DB 질의는 `lib/db.ts`. 표 만들기: `vercel env pull .env.local` → `npm run db:setup`.
- 캡처 이미지는 Vercel Blob `captures/` 에 둔다. 다시 찍으면 이전 파일을 지운다.
- 이 저장소는 공개다. 명단 · 프로젝트는 DB, 첫 화면 캡처는 Blob(`kca-vibe-captures`, 서울 `icn1`, 공개 읽기)에만 두고 저장소에 넣지 않는다. 시험 데이터는 가짜 이름으로 넣고 관리 화면 '모두 지우기'로 지운다.

## 6. 사이트 올리기 상세

- **주소 확인:** `https://<이름>.vercel.app` 만 받는다 (`capture-test` 에서 검증한 규칙). 배포마다 생기는 긴 주소는 로그인 보호 때문에 남에게 안 열리므로 "기본 주소(Domains)를 넣으세요"라고 안내한다.
- **첫 화면 캡처 (`lib/capture.ts`):** 저장하면 응답을 보낸 뒤 서버가 찍는다(`after`). "찍는 중" → 이미지, 저장 버튼이 '다시 찍기'가 된다. 페이지가 열리면(load) 네트워크가 조용해질 때까지 최대 10초 기다리고 — 지도 · 계속 갱신하는 앱은 조용해지지 않으므로 그때 있는 화면을 찍는다 — 한글 폰트(Noto Sans KR, `fonts/`)를 넣고 1.5초 뒤 1280×800 webp로 찍는다. 한 인스턴스에서 Chromium은 2개까지만 돈다. 저장 2분 뒤에도 '찍는 중'이면 실패로 보여 다시 찍게 한다. 캡처 기능은 외부에 열지 않고 등록된 주소만 찍는다.
- **30명 동시 등록 리허설 (2026-10-26, 미리보기):** 저장 응답 1.5초, 캡처 30/30 성공 · 중간값 8.9초 · 가장 느린 것 22초. 첫 시도에서 3D 지도 페이지 5건이 '네트워크 조용해질 때까지' 기다리다 30초 제한에 걸려, 최대 10초만 기다리게 고쳤다.
